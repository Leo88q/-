# 09. Донаты, цели и Care Endowment (ядро фиджитал-экономики)

## 09.1. Почему донат ≠ платёж владельцу

Главный риск всех «donate-to-pet» проектов — игрок платит «на кролика», а деньги уходят человеку, и у человека появляется стимул **демонстрировать нуждаемость** (худшая клетка, болезни, «пожалейте»). Мы ломаем это архитектурно:

```
Донат → DonationRouter
          ├── 80% → Care Endowment конкретного кролика (TBA), трата ТОЛЬКО через MerchantGateway
          ├── 10% → Streaming & Community (инфраструктура эфира, модерация, клипы)
          └── 10% → Welfare Reserve (постоянное содержание rescue, экстренная вет-помощь)
```

- `MerchantGateway` — whitelisted-контракт: сено, гранулы, зелень, наполнитель, игрушки, вет-услуги, оборудование, ремонт. Оплата **вендору в стейблах**, из дохода операционной деятельности, а не «из кармана владельца».
- Владелец **не может** вывести энддаумент ни при каких условиях: ни продажа, ни «компенсация», ни «возмещение затрат». Единственный путь энддаумента — товар или услуга для этого животного (или, после LEGACY, в Welfare Reserve по 01.7).
- Прозрачность: каждый расход энддаумента = запись `EndowmentReceipt{item, qty, vendorHash, daysCovered, oracleSig, photoHash}`. В интерфейсе: «Нимбус: сено Timothy 3.6 кг → 12 дней запаса. Осталось 4 дня. Спасибо @ivan (2 $) и @anna (5 $)».

## 09.2. Каталог объектов доната (что можно оплатить)

Три категории, с разным потоком денег — чтобы не смешивать «заботу» и «роскошь»:

| Категория | Примеры | Куда идёт | Примечание |
|---|---|---|---|
| **Necessity** (необходимое) | CareInvoice-нехватка, сено, вода, наполнитель, когти, ветеринария | 100% в Endowment (как обычно: 80/10/10) | Приоритетная очередь у персонала; не требует согласия владельца |
| **Enrichment** (развлечение) | прогулка, play-session, тоннель, пазл, тема вольера, фотосессия | 80/10/10 + 100% исполняет резиденция по SLA | Нужно согласие владельца на дату (иначе авто-перенос 72 ч) |
| **Celebration** (праздник) | день рождения, именной слот, табличка, «Golden Hay» | 80/10/10 + scarcity-лимит | Публичное событие в эфире |

**Почему Necessity идёт без согласия владельца:** если животное голодает или больной, право голоса у того, кто платит, а не у того, кто «забыл заплатить». Это же снимает регуляторный риск «принудительных платежей»: платит донатер добровольно, а исполнитель — резиденция.

## 09.3. Donation Goal (цель с авто-возвратом) — ключевой UX

```solidity
struct Goal {
  uint256 rcnId;
  GoalKind kind;         // HUTCH_REFRESH, VET_EMERGENCY, NEST_BOX, BIRTHDAY, WALK_WEEK, SANCTUARY_FOSTER
  uint64 targetClover;   // например 12 000 C ($600) за «ремонт клетки»
  uint64 raisedClover;
  uint64 deadline;
  VendorQuote quote;     // фиксированная смета от резиденции (позиции + цены)
  GoalState state;       // ACTIVE, FUNDED, EXECUTING, REFUNDING, EXPIRED
  bool   overfundingToWelfare; // излишек → welfare (по умолчанию да)
}
```

Правила, которые делают донат безопасным:
1. **Фиксированная смета.** Не «соберём сколько соберём», а «3 полки + укрытие 2 входа + защита проводов = 12 000 C». Смету публикует резиденция, изменения — только новой версией Goal (подпись 2/3 оператора).
2. **Дедлайн.** Не собрано к дедлайну → 100% авто-возврат в CLOVER (или USDC, по выбору донатера) без запроса. Это убирает «сбор ради сбора».
3. **Срок исполнения.** FUNDED → исполнение ≤14 дней (для Necessity ≤72 часа). Не исполнили → возврат + штраф резиденции в Welfare Reserve (2% от суммы) — **штрафует систему, а не просителя**.
4. **Излишек** (>100%) → по умолчанию 50% «улучшение по той же смете», 50% в Welfare Reserve. Владелец не получает разницу.
5. **Публичный статус:** «собрано 8 400/12 000 C, 43 донатера, докуплено 2 позиции, осталось 3 дня». Это то, ради чего люди возвращаются.

## 09.4. Пресеты целей (каталог, чтобы не изобретать каждый раз)

## 09.5. Слон «донат на что угодно»: конструктор

Любой адрес может создать `CustomGoal` для любого кролика: описание ≤280 символов, смета, дедлайн ≥7 дней. Требования, чтобы не превратить это в «барахолку»:
- цель должна относиться к **одному из разрешённых классов** (`GoalKind.allowlist`) и иметь смету из каталога резиденции или внешнего вендора (иначе `quote.required`);
- донатер-создатель вносит 10% депозит (burn при отмене без причины, возврат при исполнении);
- модерация: ИИ-префильтр + сообщество (3 репорта = пауза до решения welfare-палаты);
- владелец кролика может **принять или отклонить** цель (не отклонить донат, а отклонить *исполнение* — тогда средства авто-возвращаются через 14 дней).

## 09.6. «Почему мне платить, если я не владелец?» — 7 наград донатеру

| # | Награда | Механика |
|---|---|---|
| 1 | CareScore буст конкретному кролику | +0.3..+1.5 welfare-балла за исполнение (не за сам факт платежа) |
| 2 | XP, уровень, серия | см. 08.3 |
| 3 | Имя в эфире/титрах | наложение на кадр «Fed by @anna», 24 часа |
| 4 | Коллекционка | EventClip, Treat-бейдж, BirthdaySponsor |
| 5 | Право голоса | 10 голосов/неделю по декору и расписанию; вес = уровень |
| 6 | Priority queue | донатер с `DonorBadge ≥ Gold` получает слот «прогулка» вне очереди 1×/мес. |
| 7 | Доля в «Legend Pool» | top-100 Generosity получают 2% пула сезона в CLOVER (в виде Endowment-пожертвований — вывод невозможен, что и есть позиционирование) |

## 09.7. Streaming-UX доната (как это выглядит)

```
[Кадр: Нимбус, 22:41, binky detected]
 ┌──────────────────────────────────────────────┐
 │  Быстрая забота (1 тап)                       │
 │  🥕 Лакомство 2$   🌿 Зелень 1.5$   💧 Вода 1$ │
 │  🚶 Прогулка 6$    🔨 Ремонт 7.5$+            │
 │  🎂 День рождения 25$                          │
 │  ── Цели: «Реновация A-07» 8 400/12 000 (70%)  │
 │  [Donation Goal] — не соберём → вернём деньги  │
 └──────────────────────────────────────────────┘
```

- Оплата: USDC/карта/Apple Pay/Google Pay через onramp; ERC-4337 paymaster платит газ; **пользователь не знает, что он в блокчейне**, пока не откроет «Verify».
- «Verify» → транзакция, хеш сметы, статус исполнения, фото-отчёт, подпись оракула. То есть блокчейн — это не фича, аReceipt.
- Дублирование на YouTube/Twitch: там работает «overlay-донат», который конвертируется в CLOVER через интеграцию (для Web2-аудитории, без кошелька, с тем же Endowment). Это критично: 60–70% выручки донатов придёт из Web2-стримов, а не из кошельков.

## 09.8. Ограничения и защита

| Защита | Правило |
|---|---|
| Анти-отмыв / анти-само-донат | Адрес не может донатить > $500/нед. в Endowment собственного RCN (иначе это «отмывка контента») |
| Анти-манипуляция целей | 1 Goal = 1 смета; нельзя создать 50 целей по 2 C для фарма XP (15 CLOVER «вход» минимум) |
| Психологическая защита донатера | «Cool-down»: после 10 донатов за сессию — обязательная пауза 5 минут + суммарный лимит/день (по умолчанию $50, меняется пользователем) |
| Возраст | 18+; «спонсорство ребёнка» — только через аккаунт родителя |
| Налоги/чеки | Каждый платёж даёт «donation receipt» (не налоговый вычет, а доказательство расхода) — юридическая конструкция в 16.4 |
| Отмена | «Necessity» нельзя отменить после оплаты; «Enrichment/Celebration» можно отменить до исполнения (пожертвование 20% в welfare за труд резиденции) |
