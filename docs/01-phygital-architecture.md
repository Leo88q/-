# 01. Фиджитал-архитектура: как токен становится животным

## 01.1. Двойной учёт (double-entry) как базовая модель

Любое событие в Warren Protocol записывается дважды, и обе записи должны сойтись:

```
        ончейн-слой                          офчейн-слой (резиденция)
  ┌───────────────────────────┐        ┌────────────────────────────────┐
  │ CareInvoice #1042         │  ←──→  │ Списание: сено 1.2кг, гранулы  │
  │ Paid (CLOVER burned)      │        │ 180г/сут, субстрат, 2 кормления│
  │ CareAttestation CID ipfs… │  ──→   │ Подтверждение оператора + вес  │
  │ WelfareScore 87.4         │  ←──→  │ Данные весов/активности/туалета│
  │ Litter #77 sealed 2/6     │  ←──→  │ Акт окрола, чипы 6 крольчат    │
  │ RCN #042 status=PENDING   │  ──→   │ Карантин 14 дней, вет-осмотр   │
  └───────────────────────────┘        └────────────────────────────────┘
```

**Правило расхождения:** если ончейн-запись и физический факт не сходятся ≥ 48 часов, событие эскалируется в `WelfareEscalation`, статус RCN переходит в `DISPUTED` (заморозка продажи/разведения), а из Welfare Reserve финансируется независимая проверка. Расхождение не наказывается для владельца — наказуема только система/персонал, потому что владелец не может зайти в вольер.

## 01.2. Идентификация животного (5 уровней)

| Уровень | Носитель | Зачем |
|---|---|---|
| **Микрочип ISO 11784/11785** | Подкожно, обязательно | Юридическая и ветеринарная идентификация, сквозная история |
| **RCN tokenId** | `tokenId = uint160(keccak256(chipId ‖ facilityId ‖ birthTs)) & mask` | Детерминированный ID: один чип → один токен, повторный минт невозможен |
| **Визуальный паттерн** | Фото nosespot/окрас + эмбеддинг (256-битный «bunny-print») | Публичная верификация «это тот же кролик» на кадрах; защита от подмены |
| **Кольцо-маркер (нецветной, съёмный)** | Ухо/ошейник-жилет с QR | Быстрая ручная сверка оператором, скан при плановых процедурах |
| **Видео-доказательство** | Хеш кадра события → `CommitmentStore` | Аудит спорных событий (рождение, передача, изъятие) |

`chipId` никогда не публикуется в открытом виде — публикуется только его `hash` с солью и сальтом, что позволяет проверить привязку, не раскрывая данные чипа (анти-стилинг и приватность).

## 01.3. Составной актив: RCN + TBA

Каждый RCN (ERC-721) имеет привязанный **Token-Bound Account (ERC-6551)** — «кошелёк кролика»:

```
RabbitCareNFT #042  ──TBA──▶  0xBUN…042
                                ├─ $CLOVER  (энддаумент на содержание)
                                ├─ $BUNNY   (накопленные роялти/призы, если разрешено)
                                ├─ ERC-1155 (бейджи, клипы, артефакты событий)
                                └─ правила: только MerchantGateway и CareEngine могут тратить
```

Зачем TBA, а не просто баланс владельца:
- **Изоляция донатов.** Деньги животного не смешиваются с деньгами хозяина и не могут быть выведены при смене владельца.
- **Преемственность.** При передаче RCN кошелёк следует за токеном: новый владелец получает энддаумент, а не обнуляет накопленное.
- **Автоплатёж содержания.** `CareEngine` списывает месячный инвойс прямо из TBA. Если средств нет — идёт очередь эскалации (01.6), а не «кролик голодает».
- **Газ.** TBA управляется через ERC-4337 с paymaster'ом: пользователь не держит нативную монету.

## 01.4. Машина состояний RCN

```
                 ┌──────────────┐  vet-pass 14d   ┌──────────────┐
   kindling ───▶ │  PENDING     │ ───────────────▶ │   ACTIVE     │
                 └──────────────┘                   └──────┬───────┘
                  ▲        │ boarding-queue                │
                  │        ▼                                ├─ breeding → PREGNANT (31д) → LACTATING (49д) → ACTIVE
           claim from litter   ┌──────────────┐            ├─ contest win → TITLE (сезон)
                  │            │  QUARANTINE  │◀── welfare ▼
                  └─────────── │  (health)    │   trigger   ┌────────────────┐
                               └──────────────┘             │  CARE_REQUIRED │
                                                            └───────┬────────┘
                                     60d unpaid + grace             │ remediation ok
                                     ┌──────────────┐  ◀────────────┘
                                     │  SEIZURE_    │── rescue auction ──▶ ACTIVE (u新 owner)
                                     │  PENDING     │── sanctuary ────────▶ SANCTUARY
                                     └──────────────┘
                               death (natural/vet) ──▶ LEGACY (burn, навсегда в зале славы)
                               owner dies (physical) ─▶ INHERIT_QUEUED (30d) ─▶ ACTIVE
                               protocol delist ───────▶ RETIRED (обмен на другой слот)
```

| Статус | Что можно | Что нельзя |
|---|---|---|
| `PENDING` | смотреть, донатить, XP | продавать, сводить, выводить |
| `ACTIVE` | всё | — |
| `PREGNANT` / `LACTATING` | смотреть, донатить, заботу | **сводить, продавать, переезд в другой город** (жёсткий ончейн-гейт) |
| `CARE_REQUIRED` (CareScore < 55) | только содержание и лечение | breeding, contests, листинг на продажу |
| `QUARANTINE` | содержание | любые публичные события |
| `DISPUTED` | содержание | transfer, breeding, sale |
| `SEIZURE_PENDING` | содержание | всё остальное |
| `SANCTUARY` | донаты, просмотр | продажа (токен остаётся у фонда, бывший владелец теряет права) |
| `LEGACY` | память, аура потомкам | что-либо |

## 01.5. Care-долг как свойство токена

`RabbitCareNFT` содержит публичный счётчик — это ядро всей мотивации:

```solidity
struct CareLedger {
  uint64  unpaidInvoices;      // просроченные инвойсы
  uint32  streakCare;          // серия оплаченного содержания
  uint32  streakMissed;        // серия пропусков
  uint64  endowmentClover;     // доступные средства на содержание (не выводятся!)
  uint16  welfareScore;        // 0..1000, из оракула
  uint16  careScore;           // 0..1000, репутация заботы
  uint32  lifeEvents;          // прогулки, события, церемонии
  uint64  floorRoyaltyGwei;    // накопленные роялти линии
  uint16  minListingBps;       // минимальная ставка листинга (растёт при плохом уходе)
}
```

`minListingBps` — недооценённая, но критичная механика: **плохой владелец не может «убежать» с прибылью.** Минимальная цена листинга = 80% от средней цены слота, пока CareScore < 55; ниже — только через `RescueAuction` (01.6). То есть экономика пренебрежения делает бросание животного убыточным.

## 01.6. Эскалация при неоплате (пошаговая, ончейн)

| День | Событие | Эффект |
|---|---|---|
| T+0 | CareInvoice не оплачен | `unpaidInvoices += 1`, −120 XP, баннер в приложении, уведомление |
| T+3 | авто-покрытие из Endowment TBA | если хватает — инвойс закрыт, статус чистый, владельцу начисляется «Debt» в $BUNNY-эквиваленте (см. 04.5) |
| T+7 | `CareRestricted` | нет breeding, contests, апгрейдов; серия просмотров доноров не идёт в статистику |
| T+14 | «Boarding-очередь» | кролик предлагается к временному патронажу; DAO/спонсор может закрыть долг в обмен на 30-дневные права резидента |
| T+30 | `CARE_REQUIRED` | welfare-палата публикует отчёт; владелец обязан либо погасить, либо согласиться на смену куратора |
| T+60 | `SEIZURE_PENDING` | RCN изымается, долг фиксируется как `CareDebt`; при будущей продаже любого RCN этого адреса долг гасится приоритетно |
| → | **Rescue Auction** | старт 1 $BUNNY, Dutch-подъём; 100% идёт на погашение долга и в Welfare Reserve, излишек — в фонд постоянного содержания конкретного кролика |
| → | **Sanctuarization** | если покупатель не найден, животное остаётся в резиденции навсегда на содержании протокола, статус `SANCTUARY`, токен остаётся у фонда, стрим продолжается с плашкой «Rescue Bunny» |

**Важно:** `SANCTUARY` — это не «штраф животному», а спасение. Животное не покидает знакомую среду и стабильную социальную группу (что критично для кроликов: разлука bonded-пары сама по себе стресс-фактор), меняется только токен-владелец.

## 01.7. Смерть,Legacy и наследование — самый деликатный слой

**Смерть (нечастый, но неизбежный сценарий) обрабатывается как ритуал, а не как «списание актива»:**

1. Ветеринарный акт (офчейн) → `WelfareOracle` публикует `DeathAttestation` (причина, дата, подпись 3/5).
2. RCN → `LEGACY`, не сжигается: токен навсегда остаётся в реестре с мемориальными метаданными (годы, выводки, титулы, любимые занятия, лучшие клипы, список доноров-друзей). **Сжигание — опция владельца, а не автомат.**
3. **CareEndowment не возвращается и не «сгорает»:** 100% остатка автоматически переводится в Welfare Reserve и на 12 месяцев публично привязывается к «подопечному из приюта», которого выбирает сообщество. Это снимает вопрос «я платил за кролика, а деньги пропали».
4. **Legacy Aura:** потомки и потомки потомков получают +2..+6 к RarityScore (зависит от CareScore при жизни и от титулов), а род «дома линии» — +1 Depth-очко. Хорошая жизнь животного увеличивает ценность его генетики. **Это центральная инновация: забота о животном — не благотворительность, а инвестиция в наследие.**
5. **Compensation tier (прозрачно и ограничено):** если смерть наступила в период, когда `welfareScore` был нижеобещанного порога по вине резиденции, владельцу выплачивается страховка из `AnimalCareInsurance` (см. 04.7): 3 месяца содержания деньгами на другой слот ИЛИ 40% от средней цены RCN текущего слота, на выбор. Если смерть наступила при `CARE_REQUIRED`/неоплате — 0.
6. **Память:** 1 раз в год — «Remembrance Warren»: стрим-марафон, мемориальный клип-набор, право владельца посадить имя в «стене» (soulbound), голосование за нового подопечного.

**Наследование владельца (физическая смерть человека):**
- Владелец RCN может бесплатно назначить 1–3 бенефициаров (ERC-6551-наследник + EOA).
- При срабатывании (`INHERIT_QUEUED`) активируется 30-дневный период с проверкой `EligibilityGate` (см. 12.6) для получателя.
- Если владение было в TBA-кошельке провайдера-наследника — передача автоматическая; если в EOA без назначения — 180-дневная публикация и переход в `CustodyReview`.

## 01.8. Что делает «фи» (физическое) проверяемым

| Механизм | Реализация | Периодичность |
|---|---|---|
| Взвешивание | Умные весы в кормушке/на входе в домику | ежедневно (автомат) |
| Счётчик кормлений | RFID-метка кормушки + ИИ-детекция еды | ≥2 раза/сут обязательно |
| Туалетный мониторинг | Счёт помета по камере (важный индикатор GI-стазиса) | ежедневно |
| Активность | Базовая линия «3 прыжка, binky, вертикальная стойка» | еженедельно, тренд |
| Когти/зубы | Ручной чек-лист грумера + фото | 30 дней / 90 дней |
| Соц. контакт | Таймер «человек в вольере» | ≥3×10 мин в неделю |
| Стресс-индикаторы | Детектор замирания/закопания, тикс-поведения | ИИ-флаги → queue |
| Аудит | Независимая вет-инспекция (внешний партнёр) | 1 раз в квартал, публичный отчёт |

## 01.9. Границы доверия (что честно сказать пользователю)

- **Ончейн гарантирует:** права, очередь, распределение, роялти, неизменяемую историю, автоплатёж содержания.
- **Ончейн НЕ гарантирует:** что кролика погладят. Это гарантирует **контракт с резиденцией + оракул + страхование + публичные данные**. Мы никогда не описываем NFT как «доказательство качества жизни животного» — только как «доказательство прав и публично верифицируемый журнал заботы».
- **Децентрализация — ограниченная и намеренная:** физический оператор остаётся централизованной точкой отказа. Мы снижаем её цену (эскроу, аудит, страховка, открытый стрим, процедура изъятия и переноса в другую резиденцию), а не притворяемся, что её нет.
