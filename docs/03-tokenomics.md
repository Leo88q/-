# 03. Токеномика: $BUNNY и $CLOVER

## 03.1. Архитектура из двух токенов + «единицы содержания»

| | **$BUNNY** | **$CLOVER** |
|---|---|---|
| Роль | Капитал протокола: управление, стейкинг, роялти, крупные расчёты | Операционная единица: еда, прогулки, ремонт, взносы, билеты |
| Стандарт | ERC-20, 18 знаков | ERC-20, 6 знаков |
| Сапплай | **100 000 000, жёсткий, без доп. эмиссии** | Эластичный, burn-and-mint, с жёстким дневным потолком |
| Якорь стоимости | Доля в комиссии протокола + право на редкие слоты | Внутренний референс 1 CLOVER = $0.05 (1 «единица содержания» = 120 г качественных кормов + доля труда) |
| Волатильность | Рыночная | **Целенаправленно подавлена**: покупка/возврат по куру курса, спред 10% |
| Кто эммитирует | Пресейл-распределение, без TGE-сейла | `MintController` по запросу `ActionRouter` (только под оплаченное действие) |
| Кто сжигает | 50% чистых комиссий → buyback-and-burn | 100% трат на «услуги протокола» сжигаются, 0% — на «услуги вендоров» (они оплачиваются иначе, см. 04.2) |
| Кому нельзя продавать | Команда/инвесторы — 4-летний вестинг + 1-летний cliff | Никому «в никуда»: любой минт требует либо фиатного/стейбл-входа, либо подтверждённого труда |

## 03.2. $CLOVER: почему не «ещё один SLP»

Болезнь утилитарных токенов GameFi — **фауцет, масштабирующийся с числом игроков, при стоке, масштабирующемся с числом новичков**. Мы ломаем эту связь тремя способами:

1. **Фауцет = оплата, а не награда.** 90% всех $CLOVER попадает в экономику через `MintController.purchase(addr, usdc)` — то есть пользователь **приносит стейбл/фиат**, и эквивалентное количество токенов минтится и тут же расходуется на действия. Бесплатный майнинг токенов отключён.
2. **Потолок эмиссии по факту сжигания (анти-SLP-правило):**

```
daily_mint_cap = max( BASE_FLOOR, 1.25 × avg_burn(last 7 days) )
BASE_FLOOR     = 120 000 CLOVER   (≈ $6k/день на «социальные» награды: XP-бонусы, airdrop ветеранам, квесты)
HARD_CAP       = 900 000 CLOVER/день (≈ $45k) — жёсткий ончейн-предел на все случаи
```

Если сжигание падает — эмиссия наград падает следом **автоматически**, без «патчей задним числом», как это делал Axie в 2022.

3. **Двухконтурная трата.** Есть два типа списаний:
   - **Protocol-spend** (услуги, которые оказывает сам протокол/резиденция: прогулка, ремонт клетки, рил-ивент) → 100% сжигается, потому что реальная работа уже оплачена из фиатного операционного бюджета.
   - **Vendor-spend** (сено, гранулы, ветеринария, оборудование) → CLOVER сжигается, а эквивалент в стейбле выплачивается вендору из `OpsVault` через `MerchantGateway`. Никто не «получает токены за сено».

## 03.3. $CLOVER: курс, вход и выход

```
покупка:  price = ref_price × (1 + demand_premium)   demand_premium ≤ 10%
возврат:  payout = ref_price × (1 − exit_fee)          exit_fee = 10% (первые 30 дней — 25%)
ref_price обновляется еженедельно модулем PegEngine:
   целевой CorridorIndex = (OpsBurn / OpsTarget) → 1.00 ± 10%
```

- **Куда идёт 10–25% exit fee:** 100% — в Welfare Reserve. Выход из токена не должен приносить денег тому, кто вышел, но должен оставаться полезным животным.
- **Зачем спред вместо рынка:** $CLOVER не имеет листингов и «свободной цены». Его задача — быть стабильной единицей измерения заботы, а не спекулятивным объектом. Это снимает главный источник разбалансировки в GameFi: игроки не могут «продать токен и уйти», им приходится тратить его на содержание (или вернуть с потерей 10% в пользу фонда).
- **Трансфер между игроками разрешён** и бесплатен (paymaster платит), что даёт peer-to-peer экономику: «оплачу тебе прогулку за твоюGenotypeCard». Но трансферы **не создают эмиссию** и учитываются как перераспределение.

## 03.5. Сжигание и дефляция $BUNNY

```
NetFees(квартал) = Σ all protocol fees − OpEx paid from treasury
BURN_SHARE = 50%  → buyback на открытом рынке (TWAP, VAMM-ограничение) + burn
GOV_SHARE  = 30%  → реферр-пул стейкеров CareBond (выплаты в $CLOVER, не в BUNNY)
WELFARE_SHARE = 20% → Welfare Reserve (стейбл)
```

При отсутствии комиссии (ранние этапы) доля burn перераспределяется в welfare. Целевой показатель: к 36 месяцу `TotalBurned ≥ 6% supply`, к 60 — `≥ 11%`.

Доходность формируется из: 30% комиссий (п. 03.5), сборов за StudTicket, платы за «Resident Pass» (часть), доходов CareBondPool от размещения оборотного капитала (только стейбл-депозиты в ликвидных протоколах с лимитом ≤ 25% пула и запретом на leverage).

**Слэшинг:** попытка эксплойта/манипуляции оракулом → −50% застейканного; подтверждённое сокрытие welfare-инцидента оператором → −100% доли команды.

## 03.7. «Единая цена заботы»: зачем $CLOVER нужен вообще

Без внутренней единицы любые цены в USD меняются вместе с курсом токена, и «донат 2 $» превращается в «донат 0.0005 BUNNY» — нечитаемую дробь. $CLOVER решает три задачи:
1. Стабильная шкала для сотен мелких позиций (см. 05).
2. Единица учёта welfare-бюджета: 1 животное-месяц = 800 CLOVER (Burrow) = 160 единиц содержания; Warren 1 120 C, Crown 1 600 C.
3. Психология: «ты купил 40 дней сена для Нимбуса» вместо «ты перевёл $2».

## 03.8. Стабилизатор: что ломается и как чинится (политика, а не надежда)

| Сценарий | Сигнал | Реакция (авто, по правилам) |
|---|---|---|
| Перегрев: сжигание ≫ минта, CorridorIndex > 1.25 | Дефицит CLOVER, очереди трат | `BASE_FLOOR` +25% на 2 недели; снижение цен на protocol-spend на 5% |
| Перегретый спрос на RCN | Floor-цена слотов растёт > 30%/мес | Увеличение числа слотов **только** вместе с подтверждённым расширением резиденции (публичный CapacityProof) |
| Обвал спроса: burn ≪ mint | Избыток CLOVER | Немедленное сокращение `BASE_FLOOR` до 50%; отключение CLOVER-наград за XP (остаются только soulbound-очки); ввод «Care Discount Sprint» — временные скидки на содержание, чтобы вернуть расходование |
| Кассовый разрыв резиденции ( OpsVault < 45 дней) | Реальный риск для животных | Приостановка всех выплат GOV_SHARE; аварийный трансфер из Treasury; публичный инцидент-отчёт; при 2 таких кварталах — перевыборы совета (13.4) |
| Обвал $BUNNY > 60% за месяц | Падение залога стейкеров | Ставки CareInvoice **не** меняются (они в CLOVER) — это firewall; buyback замораживается на 30 дней, 100% комиссий идёт в welfare |
| Бот-фауцет (масс-активность ради наград) | 1 адрес = много « Witness » | Proof-of-Attention с daily-cap, device-attestation, «случайные капчи-события» в стриме (назови предмет в кадре) — см. 11.10 |

## 03.9. Что запрещено ончейн (жёсткие константы)

```solidity
uint256 public constant MAX_CLOVER_MINT_PER_DAY     = 900_000e6;
uint256 public constant MAX_CLOVER_REWARD_PER_ADDR_D = 250e6;      // антифарм
uint256 public constant MAX_DAILY_TRANSFER_AMOUNT   = 5_000e6;     // 1 адрес/сутки, вне protocol-routes
uint256 public constant MAX_LEVERAGE_ON_BOND_POOL   = 0;           // нет займа под залог
uint256 public constant MAX_OPS_ALLOCATION          = 25e4;        // ≤25% CareBondPool в DeFi-размещении
uint256 public constant EXIT_FEE_MIN_BPS            = 1000;
uint256 public constant WELFARE_FEE_MIN_BPS           = 1000;       // 10% всегда идёт в welfare — нельзя голосом уменьшить
```

Последняя константа — самая важная: **сообщество не может проголосовать за уменьшение доли фонда содержания.** Это снимает классический конфликт «DAO урезает бюджет на животных ради токена».
